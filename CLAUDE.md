# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Одностраничный сайт банкетного ресторана «Гурман» (Тюмень, ул. Линейная, 66), домен `ресторан-гурман.рф`. Аудитория — взрослые люди, стиль аристократический: бордо + золото, антиква, крупный шрифт. Сайт для мамы Виктора, правки обычно мелкие и точечные.

Это чистая статика: одна страница `index.html` (под банкеты) и `styles.css`, без сборки, без зависимостей и без линтера/тестов. JS один: короткий inline-скрипт в конце `index.html` (появление блоков при прокрутке через `IntersectionObserver`), без библиотек, плюс счётчик Яндекс Метрики (id 113656126, код в `<head>` и `<noscript>` сразу после `<body>`, вебвизор и карта кликов включены). При локальной проверке запросы к `mc.yandex.ru` лучше блокировать, чтобы не засорять статистику. Цели (тип «JS-событие», условие «Совпадает») заведены в кабинете Метрики, в коде они отправляются обработчиком кликов по `data-goal` в конце `index.html` (параметры `place`, `menu`, `via` берутся из `data-place`, `data-menu`, `data-via`): `call_banquet` (главная конверсия, `place`: promo, hero, contacts), `call_restaurant`, `call_delivery`, `menu_open`, `menu_download`, `menu_share`, `ny_poster`, `ny_menu` (удалить цели вместе с промо), `map_open`, `contacts_seen` (блок контактов показался на экране). Новая ссылка, которую надо считать, получает `data-goal` с идентификатором существующей цели или новую цель в Метрике. Шрифты (PT Serif, PT Mono) грузятся с Google Fonts. Дизайн от 2026-10-16: кремовый фон, вишнёвый и золото из Figma-макета меню, кнопки-пилюли; спека и план в `docs/superpowers/` (по ходу работы дизайн ушёл от спеки: отдельной страницы `/menu/` нет, шапки и липкой панели нет, актуальное состояние описано здесь). Дизайн правился в приватном Artifact на claude.ai («Гурман: главная»), боевой сайт собран по нему.

## Команды

```bash
# локальная проверка так же, как на сервере
docker build -t gurman-test . && docker run --rm --name gurman-test -p 8089:80 gurman-test   # http://localhost:8089
```

Отдельной dev-сборки нет: можно просто открыть `index.html` в браузере.

Деплой: push в `main` → GitHub Actions (`.github/workflows/deploy.yml`) собирает образ `nginx:alpine`, пушит в GHCR с тегом sha и по SSH обновляет `/opt/apps/gurman` на VPS. Пушить только по явной просьбе: это сразу выкатывает на прод.

## Правила правок

- Отдельной формы заявки нет, заказ банкета только по телефону; бэкенд не нужен.
- Цифры в телефонах и ценах с `lining-nums` (задано на `body`): старостильные цифры заказчик отклонил.
- Основной размер текста 19 px на телефоне (20 px на десктопе), подписи PT Mono не меньше 14 px, текст с контрастом не ниже 5:1, кнопки от 54 px высотой. Не мельчить ради «красоты».
- Допустимые поводы на сайте: свадьбы, юбилеи, корпоративы. Описания блюд и текст «О ресторане» без подтверждения заказчика не писать.
- Фото залов и блюд не генерировать: на сайте должны быть реальные.
- Анимации промо (снег, мерцание, блик по золоту, пульс кнопки) только CSS и тоже отключаются при `prefers-reduced-motion`. Для `mix-blend-mode: screen` у картинок промо нельзя ставить `z-index` и анимировать `opacity` на их контейнеры (`.ny-in`, `.ny-stage`), иначе наложение не работает и видна чёрная подложка (появление анимируется на самих картинках). Появление текста промо при загрузке: заголовок, «Шик» дорисовывается слева направо (`clip-path`), подпись, цены, подарки и кнопки по очереди, всё около 3 с.
- Анимации: «дыхание» фото в hero (CSS, 26 с), подъём текста hero при загрузке (CSS) и плавное появление блоков при прокрутке (CSS `.js …` + скрипт ставит класс `.in`). Всё отключается при `prefers-reduced-motion`, без JS блоки видны сразу. Новые блоки, которым нужно появление, добавлять в список селекторов и в CSS, и в скрипт. У всех `<img>` заданы `width`/`height` (нет сдвигов вёрстки); у фото в `.ph` и мозаике высота перебивается в CSS (`height: auto` / `100%`). Библиотеки анимаций не подключать без решения.
- Тексты под заголовками блоков короткие (до 4 строк на телефоне), абзацем, без принудительных переносов; блоки выровнены по левому краю.
